# Setup Guide

This guide documents the lab setup used for the Enterprise SOC Monitoring & Threat Hunting Platform using Splunk.

## Environment

The project was implemented as a single-machine SOC lab environment using Windows 10/11.

### Components

- Splunk Enterprise 10.4.1
- Splunk Universal Forwarder 10.4.1
- XAMPP 8.x
- DVWA
- BOTSv1
- BOTSv2
- BOTSv3

Additional Splunk components used in the project include:

- Palo Alto Add-on 3.8.2
- TA-Suricata 2.3.3
- Symantec EP Add-on 2.3.0
- Splunk CIM 4.12.0

## Architecture

The lab uses the following data flow:

DVWA → Apache → Splunk Universal Forwarder → TCP 9997 → Splunk Enterprise

BOTSv1, BOTSv2, and BOTSv3 are used as pre-loaded historical security datasets.

## Splunk Enterprise

Splunk Enterprise acts as the central SIEM platform for:

- Log indexing
- Security event searching
- SPL-based analysis
- Threat hunting
- Dashboard visualization
- Detection
- Alerting
- MITRE ATT&CK mapping

Splunk Web is accessed locally through:

`http://localhost:8000`

## Splunk Universal Forwarder

The Universal Forwarder monitors Apache access logs generated by the DVWA/XAMPP environment and forwards them to the local Splunk indexer.

### inputs.conf

Location:

`C:\Program Files\SplunkUniversalForwarder\etc\system\local\inputs.conf`

Configuration:


[monitor://C:\xampp\apache\logs\access.log]
index = dvwa
sourcetype = access_combined
disabled = false


Configuration:

ini
[monitor://C:\xampp\apache\logs\access.log]
index = dvwa
sourcetype = access_combined
disabled = false

outputs.conf

Location:

C:\Program Files\SplunkUniversalForwarder\etc\system\local\outputs.conf

Configuration:
[tcpout]
defaultGroup = splunk_indexer

[tcpout:splunk_indexer]
server = 127.0.0.1:9997

DVWA

DVWA is hosted through the XAMPP Apache server and acts as the live web application target.

Local URL:

http://localhost/dvwa

The environment is used to simulate:

Brute Force
SQL Injection
Cross-Site Scripting (XSS)

Apache access logs generated by these activities are monitored by the Universal Forwarder.

Data Flow
DVWA generates web application activity.
Apache records requests in access.log.
Splunk Universal Forwarder monitors the Apache log.
The Universal Forwarder forwards events to Splunk Enterprise over TCP port 9997.
Splunk Enterprise indexes the events in the dvwa index.
SPL queries are used for analysis and detection.
Dashboards visualize security activity.
Configured alerts identify selected attack patterns.
Dashboard Development

Dashboards were developed using the following workflow:

Explore available sourcetypes and fields.
Develop SPL queries.
Analyze events using commands such as stats, timechart, eval, rex, spath, and mvexpand.
Select appropriate visualizations.
Save queries as dashboard panels.
Document findings and relevant MITRE ATT&CK mappings.
Validation

After configuration, verify that:

Apache is running through XAMPP.
DVWA is accessible.
The Universal Forwarder is running.
Apache access.log is being generated.
Splunk Enterprise is receiving forwarded events.
Events are searchable in the dvwa index.
BOTSv1, BOTSv2, and BOTSv3 data are available.
Dashboard panels return expected results.
Lab Scope

This project is a controlled cybersecurity lab environment designed for security monitoring, threat hunting, detection engineering, and attack simulation.

DVWA is intentionally vulnerable and should only be used in an isolated and controlled environment.
