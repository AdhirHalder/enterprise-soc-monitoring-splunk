# SQL Injection Alert

## Alert Overview

The `SQL_Injection_Attack_Detected` alert is designed to identify potential SQL Injection activity against the DVWA application.

The alert monitors SQL Injection-related events generated by the DVWA environment.

## Alert Configuration

| Parameter | Configuration |
|---|---|
| Alert Name | `SQL_Injection_Attack_Detected` |
| Data Source | DVWA SQL Injection logs |
| Sourcetype | `dvwa:sqli` |
| Trigger Condition | SQL Injection-related patterns detected in web requests |
| Severity | High |
| Action | Alert / notification and configured response |

## Detection Indicators

The documented SQL Injection detection monitors patterns including:

- `UNION SELECT`
- `OR 1=1`
- `--`

These patterns are used to identify potential SQL Injection attempts in the monitored web traffic.

## Alert Response

When the configured detection condition is met, Splunk generates an alert for investigation.

The analyst should review:

- Source IP address
- HTTP request
- SQL Injection payload
- Targeted endpoint
- Event timestamp
- Related requests from the same source

## SOC Investigation

After the alert triggers, the analyst should:

1. Validate the suspicious HTTP request.
2. Identify the source IP.
3. Examine the SQL Injection payload.
4. Review the targeted DVWA endpoint.
5. Check for related activity from the same source.
6. Correlate the event with other available security telemetry.
7. Document the investigation and escalate if required.

The corresponding Real-Time DVWA SQL Injection Attack Dashboard provides visibility into SQL Injection activity.

## Notification Status

The alert action is configured in Splunk.

External email delivery should only be considered successful if delivery has been independently verified in the test environment.
