# SOC Architecture

## Overview

The project implements a hands-on Security Operations Center (SOC) monitoring and threat hunting environment using Splunk Enterprise as the central SIEM platform.

The lab combines historical security datasets with a live vulnerable web application to demonstrate security monitoring, log analysis, threat hunting, detection engineering, IOC correlation, dashboarding, and alerting.

## Lab Architecture

The primary lab environment is implemented on a single Windows host.

### Core Components

- Splunk Enterprise 10.4.1
- Splunk Universal Forwarder 10.4.1
- XAMPP 8.x
- DVWA (Damn Vulnerable Web Application)
- BOTSv1
- BOTSv2
- BOTSv3
- Apache Web Server
- Splunk Common Information Model (CIM)
- Suricata
- Palo Alto Add-on
- Symantec Endpoint Protection Add-on

DVWA Log Collection

Apache access logs generated by the DVWA environment are monitored using the Splunk Universal Forwarder.

Example input configuration:

[monitor://C:\xampp\apache\logs\access.log]
index = dvwa
sourcetype = access_combined
disabled = false


The Universal Forwarder sends collected events to the local Splunk Enterprise instance.

Example output configuration:

[tcpout]
defaultGroup = splunk_indexer

[tcpout:splunk_indexer]
server = 127.0.0.1:9997


Splunk Processing Workflow

Security telemetry follows the following workflow:

Security activity generates logs.
Logs are collected by the Universal Forwarder or provided through the BOTSv datasets.
Events are forwarded to or loaded into Splunk Enterprise.
Splunk indexes the security events.
SPL searches are used for investigation and threat hunting.
Detection logic identifies suspicious activity.
Dashboards visualize security events and trends.
Alerts are configured for selected attack scenarios.
Findings are mapped to relevant MITRE ATT&CK techniques.
Data Sources
BOTSv1

BOTSv1 provides historical enterprise security telemetry used for SOC monitoring, investigation, and threat hunting.

BOTSv2

BOTSv2 provides additional enterprise security events covering network, endpoint, identity, database, web, and cloud-related activity.

BOTSv3

BOTSv3 provides security telemetry for cloud, identity, endpoint, firewall, DLP, and other security monitoring scenarios.

DVWA

DVWA provides a controlled vulnerable web application environment for generating and monitoring web attack activity

The live DVWA environment is used to demonstrate:

Brute Force attacks
SQL Injection
Cross-Site Scripting (XSS)
Detection and Monitoring Layer

The Splunk monitoring layer includes:

Threat hunting

Architecture Objective

The objective of the architecture is to demonstrate an end-to-end SOC workflow in which security telemetry is collected, centralized, analyzed, visualized, investigated, and mapped to adversary techniques using Splunk.
